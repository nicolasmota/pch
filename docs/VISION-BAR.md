# Gauntlet bar — `docs/VISION.md`

**Frozen:** 2026-08-26  
**Role:** this file is the critic’s only quality bar. Do not move the bar to match the draft. Do not grade the author’s intent.

This is not “make it longer” or “make it more complete.” Completeness already lost. The bar is **community-winning**: a stranger in the MCP / local-first / agent-runtime crowd would share this, try the Hub, or argue with it.

## Who the reader is

A person who already uses Cursor, Claude Code, ChatGPT, or OpenClaw. They have 3 minutes, not 30. They have seen “AI memory” pitches. They are allergic to vapor and to architecture novels.

## Blind comparison (use when possible)

Imagine two tabs, labels stripped:

- **A** — this `VISION.md`
- **B** — a short category-defining essay (Ink & Switch *Local-first software* in spirit: one enemy, one thesis, enough mechanism to believe it, a clear “what to do Monday”)

The critic must say which they would **paste into a Discord** and why. If they pick B, the vision **loses**.

Also contrast, in one sentence each, against:

- ChatGPT / Claude product memory (vendor lock)
- Mem0 / Zep / “memory layer” startups (usually embeddings + retrieval, not a person-owned situation package)
- OpenClaw / agent runtimes (they *are* the agent; they should consume this, not replace it)

If a reader cannot tell this project apart from those three after the opening, it **loses**.

## Pass / fail criteria (all must pass to WIN)

A stranger, after the **first screenful plus the killer demo** (not after chapter 35):

1. **Thesis recall** — Can quote or closely paraphrase: *Your agent can change. Your context shouldn’t.*
2. **Enemy** — Can name the problem in one sentence: fragmented, vendor-owned memory; not “we need better RAG.”
3. **Category** — Can say this is a **user-owned context layer** (portable representation + assembly for a situation), not a chatbot, not a new model, not a vector DB.
4. **Why now** — Feels timely (many agents, MCP exists, memory is trapped per runtime) without a history lecture.
5. **What’s real** — Can list what already ships (local Hub, MCP, grants, Calendar/Gmail plugins) vs what is next (engine) vs what is later (intelligence/agency).
6. **Monday action** — Knows one concrete next step: install/run the Hub, or the portability demo, or “spec E1.”
7. **Killer demo** — Can retell: two agents, one context, a correction that follows the person. Not a stack diagram.
8. **Shareable** — Would post the link without “sorry it’s long.” A document that requires a table of contents to reach the point **fails** this criterion even if the ideas are good.
9. **Honest** — Does not sell Personal Intelligence/Agency as if they exist. Shipped work is not relitigated as vision.
10. **Single spine** — The thesis is not restated in five isomorphic chapters. Mechanism appears once. Roadmap appears once.

## What “revolutionary” means here (inspectable)

Not: invent a new field, 35 numbered sections, or more primitives.

Yes: become the **named category** people use in conversation — “that’s a context layer problem, not a memory problem” — the way “local-first” named a stance.

## What the critic inspects

The file `docs/VISION.md` as it actually is. Counts, quotes, structure. Never the changelog, never a summary written by a builder.
